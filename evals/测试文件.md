# AlgoGuide RAG 检索测试记录

## 1. 测试目标

本测试只评估 RAG 检索和低置信度过滤，不调用大模型，不需要 API Key，也不评价生成答案质量。

测试分为两层：

1. `retrieve_with_scores(query, k=3)`：检查原始检索排序。
2. `build_context(query)`：检查低置信度门控是否接受知识库内问题、拒绝知识库外问题。

`build_context()` 返回值中使用以下字段：

| 下标 | 字段 | 用途 |
|---:|---|---|
| 4（索引 3） | `used_rag` | 是否通过门控并使用知识库 |
| 6（索引 5） | `rag_confidence` | 检索置信度 |
| 7（索引 6） | `retrieval_mode` | `hybrid`、`semantic`、`lexical` 或 `none` |
| 8（索引 7） | `low_confidence_reason` | 拒绝原因 |

## 4. 评测指标

| 指标 | 统计口径 |
|---|---|
| Hit@1 | 知识库内问题的第 1 条结果是否来自任一正确来源 |
| Hit@3 | 知识库内问题的前 3 条是否包含任一正确来源 |
| MRR | 第一个正确来源排名倒数的均值；未命中记 0 |
| nDCG@3 | 单个二元相关来源下按排名折损；前三未命中记 0 |
| 有答案问题接受率 | `answerable=true` 且 `used_rag=true` 的比例 |
| 知识库外问题拒绝率 | `answerable=false` 且 `used_rag=false` 的比例 |
| 误接受数 | 知识库外问题却启用 RAG 的数量 |
| 误拒绝数 | 知识库内问题却被门控拒绝的数量 |
| P50/P95 | 每次原始检索调用耗时的第 50/95 百分位 |
| 检索模式次数 | `build_context()` 的 `semantic`、`lexical`、`none` 次数 |

脚本会在结果中记录操作系统、处理器、Python 版本、embedding 模型、知识块数量、预热次数和每题重复次数。

## 6. 仅用开发集选择阈值

依次测试 `0.20、0.25、0.30、0.32、0.35、0.40、0.45`：

```powershell
$values = 0.20, 0.25, 0.30, 0.32, 0.35, 0.40, 0.45
foreach ($value in $values) {
  $tag = $value.ToString("0.00").Replace(".", "")
  python .\evals\rag_eval.py `
    --repo . `
    --dataset .\evals\eval_questions.jsonl `
    --split dev `
    --k 3 `
    --runs 5 `
    --warmup 5 `
    --semantic-threshold $value `
    --lexical-threshold 2 `
    --output ".\evals\results\result_dev_$tag.json"
}
```

选择规则：

1. 只保留知识库外问题拒绝率 `>= 90%` 的阈值。
2. 在满足条件的阈值中，优先选择有答案问题接受率较高者。
3. 接受率相同时选择 MRR 较高者；MRR 是原始排序指标，通常不会随门控阈值变化，可作为并列参考。
4. 确定后冻结阈值、代码、知识文档和索引，不再根据 `test` 结果调整。

## 8. 失败结果分析

打开 `result_test_final.json` 的 `cases` 数组逐条检查：

- Hit@3 失败：检查知识文档是否覆盖该问法、切块是否合理、embedding 模型是否正确加载。
- Hit@3 命中但 `used_rag=false`：阈值可能偏高，或相似度分数分布与阈值不匹配。
- 库外问题 `used_rag=true`：阈值可能偏低，或某个知识块表述过于宽泛。
- `lexical` 次数较多：检查 FAISS 依赖、索引文件和 embedding 模型加载错误。
- 同一来源重复占据前三：检查切块去重和文档级结果多样性。

不同机器的延迟不能直接比较。修改知识库、切块、embedding 模型、阈值或检索代码后，必须重建索引并重新跑完整评测。

需要区分两种“拒绝”：

- RAG拒绝：不使用知识库、不返回来源。本次知识库外问题为100%。
- 助手拒答：明确表示无法基于知识库回答。本次为0%；模型仍直接回答了Java GC、Redis缓存穿透、死锁、CNN池化和量子纠错问题。

因此，当前项目的最终答案表面正确率较高，但不能据此认为RAG质量良好。最主要风险是模型利用自身知识补全答案，同时返回大量不相关来源，造成“回答正确但证据不可靠”。

## 11. 来源去重与混合排序修复

1. 同一个来源文件只保留最高分片段，禁止一个文件重复占据Top-3。
